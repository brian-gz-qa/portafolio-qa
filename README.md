## 🚀 Proyectos

### 1️⃣ Urban Routes — Pruebas de aplicaciones web (Sprint 3)

- **Problema:** Validar la calidad de una aplicación web de alquiler de automóviles compartidos (funcionalidades de "Compartir un automóvil", método de pago y proceso de reserva).
- **Qué hice:** Diseñé y ejecuté casos de prueba funcionales y exploratorios en Chrome y Firefox. Documenté 10+ bugs en Jira, incluyendo 2 críticos (validación rota en campos de tarjeta y reserva sin método de pago).
- **Resultado:** Proyecto **aprobado al 100%** por el revisor. Aprendí a aislar variables, identificar causas raíz y reutilizar tickets de bugs para flujos finales.

📁 Evidencias: [`Sprint_3_Pruebas_Web/`](Sprint_3_Pruebas_Web/QA_Urban_Routes_Sprint_3.md)

### 2️⃣ Urban Routes — Pruebas de API (Sprint 4)

- **Problema:** Verificar la calidad del backend `/api/v1/kits/...` de Urban Routes (agregar productos a kits).
- **Qué hice:** Diseñé y ejecuté **60 casos de prueba** de API en Postman cubriendo valores límite, tipos de datos inválidos, payloads vacíos e IDs inexistentes. Documenté 6+ bugs con severidad y prioridad.
- **Resultado:** Proyecto **aprobado**. Identifiqué bugs de alta severidad (500 Internal Server Error con tipos inválidos, fallo silencioso con IDs inexistentes) y aprendí a distinguir severidad vs. prioridad.

📁 Evidencias: [`Sprint_4_Pruebas_API/`](Sprint_4_Pruebas_API/)

### 3️⃣ Urban Routes — Casos de prueba y análisis de requisitos (Sprints 1 y 2)

- **Problema:** Analizar los requisitos de la app Urban Routes y diseñar la estrategia de pruebas inicial.
- **Qué hice:** Creé mapas mentales de funcionalidades, casos de prueba con **clases de equivalencia**, **valores límite** y **Pairwise testing**.
- **Resultado:** Base sólida de técnicas de diseño de pruebas aplicadas a un caso real.

📁 Evidencias: [`Sprint_1_Introduccion/`](Sprint_1_Introduccion/) y [`Sprint_2_Tecnicas_Pruebas/`](Sprint_2_Tecnicas_Pruebas/)
